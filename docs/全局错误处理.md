# 全局错误处理

## 架构概览

错误处理分五层，异常在**源头**就被分类为 `AgentError`，下游各层只需 `except AgentError: raise` 透传，最终在 `ChatAgent` 层转换为用户友好的气泡提示。

```
┌─────────────────────────────────────────────────────────┐
│  Layer 0: 源头包装层                                      │
│  ├─ LLMWrapper (providers/llm.py)                        │
│  │   包装 BaseChatModel.ainvoke，原始异常 → AgentError     │
│  └─ CloudEmbeddingFunction (memory/store.py)             │
│      _embed() 抛带 [embedding/dashscope] 前缀的异常       │
│      store 各方法用 _is_embedding_error() 检测并分类      │
├─────────────────────────────────────────────────────────┤
│  Layer 1: LangGraph 节点层 (agent/chat/nodes.py)         │
│  ├─ _retry_llm_call                                      │
│  │   只重试瞬态错误（429/超时/5xx），401/403 直接抛         │
│  ├─ CustomToolNode                                       │
│  │   except AgentError → raise | except Exception → 降级  │
│  └─ memory_node                                          │
│      manager 未就绪 → raise CONFIG_MISSING_EMBED_KEY       │
├─────────────────────────────────────────────────────────┤
│  Layer 2: Graph 层 (agent/chat/graph.py)                 │
│  └─ run_chat                                              │
│      except AgentError → raise | except Exception → 兜底   │
├─────────────────────────────────────────────────────────┤
│  Layer 3: ChatAgent 层 (agent/chat/chat_agent.py)        │
│  └─ chat()                                                │
│      except AgentError → 生成 ChatResponse → 发布 RESPONSE  │
├─────────────────────────────────────────────────────────┤
│  Layer 4: UI 层 (pet/pet.py)                             │
│  └─ _on_agent_response                                   │
│      渲染气泡（精确提示 + 操作建议 + 对应表情）              │
└─────────────────────────────────────────────────────────┘
```

## 核心组件

### AgentError 枚举 (`core/errors.py`)

定义 26 种错误类型，每种包含：

- `user_message`：用户友好提示（宠物语气）
- `action_hint`：操作建议（去哪里修）
- `emotion`：宠物情绪表情

```python
from core.errors import AgentError, ErrorCode

# 枚举分类映射器
ae = AgentError.classify(original_exception)
# → AgentError(code=ErrorCode.LLM_AUTH_INVALID, user_message="...", action_hint="...", emotion="confused")
```

### LLMWrapper (`providers/llm.py`)

包装 `BaseChatModel`，在 `ainvoke` / `invoke` 出口处捕获异常并分类：

```python
class LLMWrapper:
    """拦截 LLM 调用，原始异常 → AgentError"""
    async def ainvoke(self, *args, **kwargs):
        try:
            return await self._inner.ainvoke(*args, **kwargs)
        except AgentError:
            raise  # 已结构化，放行
        except Exception as e:
            raise AgentError.classify(e) from e
```

### CloudEmbeddingFunction (`memory/store.py`)

Embedding 异常处理的特殊之处：**ChromaDB 会吞异常类型**。

```
_embed() 抛 AgentError
  → ChromaDB collection.query() 内部 catch
    → 重新抛为普通 Exception（附加 " in query." 后缀）
      → 原始异常类型丢失！
        → store.search() 的 except AgentError 匹配不到
          → 被 except Exception: return [] 吞了
```

解决方案：`_embed()` 不抛 `AgentError`，改为抛带 `[embedding/dashscope]` 前缀的普通 `Exception`。下游用 `_is_embedding_error()` 检测前缀并分类：

```python
@classmethod
def _is_embedding_error(cls, e: Exception) -> Optional[AgentError]:
    """检测异常是否来自 embedding API"""
    msg = str(e)
    if "[embedding/dashscope" not in msg:
        return None
    # 按消息关键词匹配 401/429/timeout/5xx
    if "authenticationerror" in msg_lower or "invalid api key" in msg_lower:
        return AgentError._build(ErrorCode.EMBED_AUTH_INVALID, original=msg)
    # ...
```

## 异常流转路径

### LLM API Key 无效

```
LLM.ainvoke()
  → LLMWrapper 捕获 AuthenticationError
    → AgentError.classify() → LLM_AUTH_INVALID
      → _retry_llm_call: 401 不可重试，直接抛
        → graph.run_chat: except AgentError → raise
          → chat_agent.chat: 生成 ChatResponse
            → 发布 RESPONSE 事件
              → 宠物气泡: "对话模型的 API Key 好像不对哦…"
```

### Embedding API Key 无效

```
store.search()
  → ChromaDB collection.query()
    → CloudEmbeddingFunction._embed() 抛 [embedding/dashscope] 异常
      → ChromaDB 包装为普通 Exception（类型丢失）
        → store.search() except Exception:
          → _is_embedding_error() 检测前缀 → EMBED_AUTH_INVALID
            → raise AgentError
              → CustomToolNode: except AgentError → raise
                → graph.run_chat → chat_agent.chat → 气泡
```

### 工具执行失败（降级）

```
tool._arun() 抛原始异常
  → CustomToolNode: except Exception → 降级返回 ToolMessage({"error": "..."})
    → LLM 收到错误信息，自行回复用户
      → 不弹错误气泡（LLM 自行处理）
```

## 重试策略

```python
_RETRYABLE_CODES = {
    ErrorCode.LLM_RATE_LIMITED,      # 429 限流
    ErrorCode.LLM_TIMEOUT,           # 超时
    ErrorCode.LLM_SERVER_ERROR,      # 5xx
    ErrorCode.NETWORK_NO_CONNECTION, # 无网络
    ErrorCode.NETWORK_DNS_FAILED,    # DNS
}
```

- **可重试**（瞬态错误）：指数退避重试 3 次
- **不可重试**（不可恢复）：401/403/SSL 证书/额度用完 → 直接抛

## 初始化阶段错误检测

### Warmup 阶段

```
app._warmup_in_background()
  → _init_embedding()
    → MemoryManager.initialize()
      → store.initialize()
        → _embed("test") 失败 → raise AgentError
  → _init_embedding() 保存错误 → embedding_ok=False
  → _check_first_run()
    → LLM Key 不存在 → 气泡: "请配置 API Key"
    → LLM 初始化失败 → 气泡: "对话模型有问题"
    → Embedding Key 不存在 → 气泡: "请配置记忆模型 API Key"
    → Embedding 初始化失败 → 气泡: "记忆模型有问题"
```

### 对话阶段

```
chat_agent.chat()
  → 前置检查: has_api_key() / has_embedding_api_key()
  → graph.run_chat()
    → memory_node: is_ready=False → raise CONFIG_MISSING_EMBED_KEY
  → except AgentError → 气泡提示（只发 RESPONSE 事件，不发 LLM_CONFIG_ERROR）
```

## 热更新

### LLM 配置变化

```
Settings 改 LLM Key → config_manager.save() → notify_listeners("*")
  → LLMProvider._on_config_change → reset()
    → 下次调用 get_llm() 重新创建实例（用新 Key）
```

### Embedding 配置变化

```
Settings 改 Embedding Key → config_manager.save() → notify_listeners("*")
  → MemoryManager._on_config_change → store.update_embedding_config()
    → 创建新 CloudEmbeddingFunction（用新 Key）
    → get_collection(embedding_function=new_ef) 重新绑定（不丢数据）
```

## 安全保障

### 维度检查不会清空记忆

初始化时 `embed_query("test")` 用来检测向量维度是否匹配。如果 Embedding Key 错误，这一步会抛异常。旧代码的 `except Exception` 会误判为"集合损坏"并 `delete_collection()`，**清空所有记忆**。

修复后：单独 try-except 包裹维度检查，embedding 错误时跳过检查、保留已有记忆、上抛 AgentError。
