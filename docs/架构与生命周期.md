# 暖宝宝架构与生命周期

本文档说明项目的核心架构、事件循环、线程模型和完整生命周期。

---

## 1. 技术栈概览

| 组件     | 技术          | 说明                            |
| -------- | ------------- | ------------------------------- |
| UI 框架  | PyQt6         | Qt 6 的 Python 绑定             |
| 异步桥接 | qasync        | 将 Qt EventLoop 与 asyncio 结合 |
| LLM 框架 | LangGraph     | 有状态的 Agent 框架             |
| 事件通信 | 自建 EventBus | 发布/订阅模式                   |
| 进程     | 单进程        | 所有组件在一个 Python 进程      |

## 3. 为什么需要这种架构？

### 3.1 PyQt6 的限制

**Qt 必须在主线程运行：**

- 所有 UI 操作（创建窗口、更新画面）必须在主线程
- Qt EventLoop 是单线程的，不能并行处理

### 3.2 LLM 的耗时特性

**LLM 调用是 IO 密集型：**

- 模型加载：2-5 秒（首次）
- API 请求：1-5 秒（每次对话）
- 如果在主线程执行，UI 会卡住

### 3.3 asyncio vs threading

| 方案              | 优点                          | 缺点                 |
| ----------------- | ----------------------------- | -------------------- |
| **多线程**        | 可以并行 IO                   | 有锁问题，Python GIL |
| **asyncio**       | 单线程高并发                  | 需要所有代码异步     |
| **混合 (本项目)** | UI 用 Qt 线程，LLM 用 asyncio | 需要事件循环桥接     |

### 3.4 qasync 的作用

`qasync.QEventLoop` 是桥梁：

```python
# 普通 Qt 程序
qt_app = QApplication(sys.argv)
app.exec()  # 阻塞在 Qt 事件循环

# 本项目用 qasync
from qasync import QEventLoop
loop = QEventLoop(qt_app)  # 创建混合循环
asyncio.set_event_loop(loop)  # 设为当前事件循环

# 现在可以同时：
# 1. Qt 事件处理（鼠标、定时器）
# 2. asyncio 任务（协程、LLM 调用）
loop.run_until_complete(main())
```

### 4.2 预热策略详解

#### 为什么需要预热？

LLM 调用有冷启动延迟：

- LangChain 模型初始化：200-500ms
- 第一次 API 调用（认证+连接）：额外 1-2s
- 如果用户第一次对话时才初始化，会感到明显卡顿

#### 预热架构

```
┌─────────────────────────────────────────────────────────────────┐
│                     两阶段预热                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  阶段1: ChatAgent._warmup_llm()                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  目标: 让 LLM 第一次调用不冷启动                          │   │
│  │                                                          │   │
│  │  在独立线程中:                                           │   │
│  │  1. providers.get_llm() → 初始化模型实例                 │   │
│  │  2. 触发 API 客户端缓存                                  │   │
│  │  3. 设置 _llm_warmed = True                              │   │
│  │                                                          │   │
│  │  耗时: 2-3s                                              │   │
│  │  失败: 发布 LLM_CONFIG_ERROR 事件                        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  阶段2: 记忆系统初始化                                          │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  目标: 让向量库第一次查询不冷启动                          │   │
│  │                                                          │   │
│  │  同步执行（在 ChatAgent 之后）:                           │   │
│  │  1. get_memory_manager() → 获取单例                      │   │
│  │  2. mem_mgr.initialize() → 加载 Embedding 模型           │   │
│  │                                                          │   │
│  │  耗时: 1-2s                                              │   │
│  │  失败: 不阻塞，跳过即可                                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  等待策略:                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  warmup_done = asyncio.Event()                           │   │
│  │  后台线程完成后: call_soon_threadsafe(warmup_done.set)   │   │
│  │  主线程等待: wait_for(warmup_done, timeout=10s)           │   │
│  │                                                          │   │
│  │  超时降级:                                                │   │
│  │  - 10秒内未完成 → 放弃等待                                │   │
│  │  - 继续显示宠物（可能功能受限）                            │   │
│  │  - AGENT_READY 事件标记 chat_agent=None                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 降级保护

| 场景         | 处理                  | 用户体验                 |
| ------------ | --------------------- | ------------------------ |
| LLM 预热成功 | 正常显示              | 立即对话，无延迟         |
| LLM 预热失败 | 发布 LLM_CONFIG_ERROR | 显示提示，可配置后重试   |
| LLM 预热超时 | 强制显示宠物          | 首次对话有延迟，后续正常 |
| 记忆系统失败 | 跳过即可              | 没有记忆功能，其余正常   |

#### 为什么不在显示后预热？

| 方案                 | 用户感知           | 问题                            |
| -------------------- | ------------------ | ------------------------------- |
| 显示后预热           | 看到宠物但对话失败 | "为什么没反应？"                |
| 预热后显示（本项目） | 看到宠物就能对话   | 最坏等10秒（但显示loading提示） |

本项目选择"预热后显示"，保证用户第一次交互就有响应。

## 5. EventBus 事件流

```
┌─────────────────────────────────────────────────────────────────┐
│                         EventBus                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  事件分类:                                                │   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐  │   │
│  │  │  SYSTEM     │  │  UI          │  │  AGENT          │  │   │
│  │  │  (系统事件)  │  │  (界面事件)  │  │  (AI 事件)      │  │   │
│  │  └─────────────┘  └─────────────┘  └─────────────────┘  │   │
│  │                                                         │   │
│  │  SYSTEM 事件:                                            │   │
│  │  • app_started      → 应用启动                            │   │
│  │  • shutdown         → 请求关闭                            │   │
│  │                                                         │   │
│  │  UI 事件:                                                │   │
│  │  • MOUSE_CLICK      → 鼠标点击                            │   │
│  │  • MOUSE_DRAG_*     → 拖拽开始/移动/结束                  │   │
│  │  • MOUSE_HOVER_*    → 悬停进入/离开                       │   │
│  │                                                         │   │
│  │  AGENT 事件:                                             │   │
│  │  • USER_MESSAGE     → UI → Agent：用户发消息              │   │
│  │  • THINKING         → Agent → UI：正在思考                │   │
│  │  • RESPONSE         → Agent → UI：回复完成                │   │
│  │  • ANIMATION_REQUEST→ 动画请求                            │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  特点:                                                          │
│  • 发布/订阅模式                                                │
│  • 同步调用（发布者的线程执行回调）                              │
│  • 跨线程安全（需要 QTimer.singleShot 桥接）                    │
└─────────────────────────────────────────────────────────────────┘
```

### 跨线程通信问题

EventBus 的回调是**在发布者的线程**执行的：

```python
# 主线程发布
event_bus.publish(USER_MESSAGE, msg)
# → ChatAgent._on_user_message() 在主线程执行 ✓

# LangGraph 可能在其他线程发布
event_bus.publish(RESPONSE, result)
# → Pet._on_agent_response() 可能在非主线程执行 ✗
#    （Qt UI 操作必须在主线程！）
```

解决方案：

```python
# Pet 中
def _on_agent_response(self, response):
    # QTimer.singleShot(0, ...) 将回调 post 到 Pet 所在线程
    QTimer.singleShot(0, lambda: self._handle_agent_response(response))
    # 这样 _handle_agent_response() 就安全地在主线程执行了
```

## 7. 线程安全注意事项

### 7.1 安全的操作

| 操作          | 线程     | 原因             |
| ------------- | -------- | ---------------- |
| QTimer 回调   | 主线程   | Qt 保证          |
| EventBus 发布 | 任何线程 | 内部无状态       |
| EventBus 订阅 | 任何线程 | 只注册，不在回调 |

### 7.2 需要桥接的操作

| 操作                      | 问题         | 解决方案                    |
| ------------------------- | ------------ | --------------------------- |
| EventBus 回调中的 UI 操作 | 可能非主线程 | `QTimer.singleShot(0, ...)` |
| ChatAgent.chat()          | async 函数   | `loop.create_task(...)`     |
| 退出流程                  | 多线程需同步 | `shutdown_event.wait()`     |

### 7.3 禁止的操作

- ❌ 在子线程直接操作 Qt UI（窗口、控件）
- ❌ 在 EventBus 回调中执行耗时操作
- ❌ 多个线程同时操作同一个 Python 对象（无锁）

## 8. 关键设计决策

### 8.1 为什么选择「预热后显示」策略？

| 方案                       | 体验                   | 问题                   |
| -------------------------- | ---------------------- | ---------------------- |
| 主线程同步初始化后显示     | 卡住 5-10 秒           | 用户看到白屏           |
| 显示后后台初始化           | 立即看到宠物           | 首次对话失败，用户困惑 |
| **后台初始化，预热后显示** | 有进度反馈，就绪后显示 | 需要超时降级保护       |

我们选择第三种方案：

1. 创建 Pet 但不显示（准备资源）
2. 后台线程初始化 Agent + 预热 LLM + 记忆系统
3. 预热完成后显示 Pet（用户看到即就绪）
4. 10 秒超时降级（避免无限等待）

详见 §4.2 预热策略。

### 8.2 为什么需要保存事件循环引用？

```python
# ChatAgent.__init__
def __init__(self, event_loop=None):
    self._main_loop = event_loop

# 为什么不直接 get_running_loop()？
# 因为 EventBus 回调可能在不同的线程执行
# 如果在后台线程执行，get_running_loop() 会失败
# 保存引用是最可靠的方式
```

### 8.3 为什么用 EventBus 而不是直接调用？

```python
# 直接调用（耦合）
pet.agent.handle_message(msg)

# EventBus（解耦）
event_bus.publish(USER_MESSAGE, msg)
# ChatAgent 自己订阅，Pet 不知道 Agent 的存在
```

EventBus 让组件独立，可以随意替换或增减组件。

## 10. 调试技巧

### 10.1 判断当前线程

```python
import threading

def some_function():
    current_thread = threading.current_thread()
    logger.info(f"Running in: {current_thread.name}")

    if current_thread.name == "MainThread":
        logger.info("✓ 主线程，安全操作 UI")
    else:
        logger.warning("⚠️  非主线程，UI 操作可能崩溃！")
```

### 10.2 判断当前事件循环

```python
import asyncio

def some_async_function():
    loop = asyncio.get_running_loop()
    logger.info(f"Event loop: {loop}")

def some_sync_function():
    try:
        loop = asyncio.get_running_loop()
        logger.info(f"在事件循环中: {loop}")
    except RuntimeError:
        logger.warning("⚠️  不在事件循环中，无法执行 async 操作")
```

## 11. 常见问题

### Q1: 为什么有时 UI 会卡住？

可能原因：

- QTimer 回调中有耗时操作（>10ms）
- asyncio 任务执行时间过长（阻塞事件循环）
- Python GC 暂停

排查方法：在耗时操作前后加日志，用时间戳计算耗时。

### Q2: EventBus 回调为什么有时不执行？

可能原因：

- 订阅者已被销毁（GC）
- 没有订阅者，事件被静默忽略
- 回调抛异常被 EventBus 捕获

排查方法：开启 EventBus 的 debug 日志。

### Q3: 如何从后台线程更新 UI？

正确做法：

```python
def background_task():
    # 直接操作 UI → 崩溃！
    pet.setText("Hello")  # ❌

    # 通过 EventBus
    event_bus.publish(UI_UPDATE, text="Hello")  # ✓

    # 通过信号
    pet.some_signal.emit("Hello")  # ✓（Qt 信号跨线程安全）
```

### Q4: shutdown_event 是什么？

一个 asyncio.Event，用于跨组件通知退出：

```python
# main.py
await shutdown_event.wait()  # 主协程等待

# anywhere
shutdown_event.set()  # 设置，所有 wait 的协程恢复
```

## 12. 总结

| 概念         | 说明           | 本项目实现                      |
| ------------ | -------------- | ------------------------------- |
| **进程**     | 独立资源空间   | 单进程                          |
| **线程**     | CPU 调度单位   | 主线程 (UI) + 后台线程 (初始化) |
| **协程**     | 用户态轻量线程 | asyncio 管理                    |
| **事件循环** | 调度协程的核心 | qasync.QEventLoop (Qt+asyncio)  |
| **桥接**     | 连接不同线程   | QTimer.singleShot, EventBus     |

**核心原则：**

1. UI 操作永远在主线程
2. 耗时操作用 asyncio 或线程
3. EventBus 解耦组件
4. 跨线程必须桥接
