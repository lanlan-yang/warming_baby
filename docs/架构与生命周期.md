# 暖宝宝架构与生命周期

本文档说明项目的核心架构、事件循环、线程模型和完整生命周期。

---

## 1. 技术栈概览

| 组件 | 技术 | 说明 |
|------|------|------|
| UI 框架 | PyQt6 | Qt 6 的 Python 绑定 |
| 异步桥接 | qasync | 将 Qt EventLoop 与 asyncio 结合 |
| Agent 范式 | Loop Engineering | 自研，while 循环实现 LLM 自主决策 |
| LLM 框架 | LangChain | 模型调用和工具绑定 |
| 记忆存储 | ChromaDB + bge-small-zh | 向量数据库 + Embedding 模型 |
| 事件通信 | 自建 EventBus | 发布/订阅模式 |
| 进程 | 单进程 | 所有组件在一个 Python 进程 |

## 3. 为什么需要这种架构？

### 3.1 PyQt6 的限制

**Qt 必须在主线程运行：**

- 所有 UI 操作（创建窗口、更新画面）必须在主线程
- Qt EventLoop 是单线程的，不能并行处理

### 3.2 LLM 的耗时特性

**LLM 调用是 IO 密集型：**

- 模型加载：2-5 秒（首次）
- API 请求：1-3 秒（每次对话）
- 如果在主线程执行，UI 会卡住

### 3.3 为什么不用 LangGraph？

| 对比项 | LangGraph (旧) | Loop Engineering (新) |
|--------|----------------|----------------------|
| 复杂度 | 高（节点、边、状态图） | 低（while 循环） |
| 可调试性 | 低（状态转换不透明） | 高（直接看循环逻辑） |
| 灵活性 | 固定流程 | LLM 自主决策 |
| Token 消耗 | 额外 System Prompt | 无额外开销 |
| 学习成本 | 需理解 LangGraph 概念 | 只需理解 Python 循环 |

Loop Engineering 用简单的 while 循环实现了相同的功能：

```python
# TurnEngine 核心逻辑（简化）
async def run(self, messages):
    for _ in range(max_steps):
        response = await llm.ainvoke(messages)
        
        if not response.tool_calls:
            return response  # 没有工具调用，返回结果
        
        # 执行所有工具调用（可并发）
        tool_results = await asyncio.gather(
            *[execute_tool(call) for call in response.tool_calls]
        )
        
        # 将结果加入消息
        messages.append(response)
        messages.extend(tool_results)
    
    raise TimeoutError("超过最大步数")
```

### 3.4 qasync 的作用

`qasync.QEventLoop` 是桥梁：

```python
# 普通 Qt 程序
qt_app = QApplication(sys.argv)
app.exec()  # 阻塞在 Qt 事件循环

# 本项目用 qasync
from qasync import QEventLoop
loop = QEventLoop(qt_app)  # 创建混合循环
asyncio.set_event_loop(loop)  # 设为当前事件循环

# 现在可以同时：
# 1. Qt 事件处理（鼠标、定时器）
# 2. asyncio 任务（协程、LLM 调用）
loop.run_until_complete(main())
```

### 4.2 预热策略详解

#### 为什么需要预热？

LLM 调用有冷启动延迟：

- LangChain 模型初始化：200-500ms
- Embedding 模型加载（记忆系统）：1-2s
- 第一次 API 调用（认证+连接）：额外 1-2s
- 如果用户第一次对话时才初始化，会感到明显卡顿

#### 预热架构

```
┌─────────────────────────────────────────────────────────────────┐
│                     两阶段预热                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  阶段1: ChatAgent._warmup_llm()                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  目标: 让 LLM 第一次调用不冷启动                          │   │
│  │                                                          │   │
│  │  在后台线程中:                                           │   │
│  │  1. providers.get_llm() → 初始化 LLM 实例               │   │
│  │  2. TurnEngine 构建（绑定工具到 LLM）                    │   │
│  │  3. 触发 API 客户端缓存                                  │   │
│  │  4. 设置 _llm_warmed = True                              │   │
│  │                                                          │   │
│  │  耗时: 2-3s                                              │   │
│  │  失败: 发布 LLM_CONFIG_ERROR 事件                        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  阶段2: 记忆系统初始化                                          │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  目标: 让向量库第一次查询不冷启动                          │   │
│  │                                                          │   │
│  │  在后台线程中（与阶段1串行）:                             │   │
│  │  1. get_memory_manager() → 获取单例                      │   │
│  │  2. mem_mgr.initialize() → 加载 Embedding 模型           │   │
│  │  3. ChromaDB collection 预热                             │   │
│  │                                                          │   │
│  │  耗时: 1-2s                                              │   │
│  │  失败: 不阻塞，跳过即可                                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  等待策略:                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  warmup_event = asyncio.Event()                          │   │
│  │  后台线程完成后: loop.call_soon_threadsafe(warmup_event.set) │
│  │  主线程等待: wait_for(warmup_event.wait(), timeout=10)   │   │
│  │                                                          │   │
│  │  超时降级:                                                │   │
│  │  - 10秒内未完成 → 放弃等待                                │   │
│  │  - 继续显示宠物（可能功能受限）                            │   │
│  │  - AGENT_READY 事件标记 chat_agent=None                  │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 降级保护

| 场景 | 处理 | 用户体验 |
|------|------|----------|
| LLM 预热成功 | 正常显示 | 立即对话，无延迟 |
| LLM 预热失败 | 发布 LLM_CONFIG_ERROR | 显示错误提示，可配置后重试 |
| LLM 预热超时 | 强制显示宠物 | 首次对话有延迟，后续正常 |
| 记忆系统失败 | 跳过即可 | 没有记忆功能，其余正常 |

### 4.3 用户对话流程

```
用户输入"你好"
    │
    ├─ 点击发送按钮
    │   (主线程 - UI 事件)
    │
    ├─ pet._on_user_input()
    │   ├─ 重置 idle timer
    │   ├─ 显示 typing 状态 "..."
    │   │
    │   └─ event_bus.publish(AGENT.USER_MESSAGE, message="你好")
    │       (主线程 - 同步调用)
    │
    ├─ ChatAgent._on_user_message()
    │   (主线程 - EventBus 回调)
    │   ├─ event_bus.publish(AGENT.THINKING)
    │   │   └─ Pet 收到 → 切换到 thinking 动画
    │   │
    │   └─ loop.create_task(chat("你好", location))
    │       (提交到 asyncio 队列)
    │
    ├─ chat("你好") 协程执行
    │   (asyncio 事件循环)
    │   │
    │   ├─ 1. MessageBuilder.build_messages()
    │   │   ├─ 构建 System Prompt（角色 + 时间 + 位置 + 记忆）
    │   │   ├─ 检索 1 条相关记忆（异步）
    │   │   └─ 添加用户输入
    │   │
    │   ├─ 2. TurnEngine.run(messages, tools)
    │   │   │
    │   │   ├─ while 循环（最多 5 步）
    │   │   │   ├─ LLM 调用
    │   │   │   ├─ 检查是否有 tool_calls
    │   │   │   └─ 并发执行工具（如果有）
    │   │   │
    │   │   └─ 返回 ChatResponse（包含 text, emotion, new_memories）
    │   │
    │   ├─ 3. 保存新记忆（如果有）
    │   │   └─ memory_manager.smart_add_memory(...)
    │   │
    │   └─ 4. event_bus.publish(AGENT.RESPONSE, chat_response)
    │       (asyncio 任务完成)
    │
    └─ pet._on_agent_response()
        (主线程 - EventBus 回调)
        ├─ QTimer.singleShot(0, ...)
        │   └─ 确保在主线程处理
        ├─ show_message(chat_response.text)
        │   └─ 显示气泡
        └─ trigger_animation(chat_response.emotion)
            └─ 播放对应动画
```

当 LLM 判断需要调用工具时：

```
用户: "今天天气怎么样"
    │
    └─ chat("今天天气怎么样")
        │
        └─ TurnEngine.run() 执行 while 循环
            │
            ├─ Step 1: LLM 调用
            │   │

            │
            ├─ Step 3: LLM 再次调用
```

## 5. EventBus 事件流

### 核心事件

```
┌─────────────────────────────────────────────────────────────────┐
│                         EventBus                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  事件分类:                                                │   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐  │   │
│  │  │  SYSTEM     │  │  UI          │  │  AGENT          │  │   │
│  │  │  (系统事件)  │  │  (界面事件)  │  │  (AI 事件)      │  │   │
│  │  └─────────────┘  └─────────────┘  └─────────────────┘  │   │
│  │                                                         │   │
│  │  SYSTEM 事件:                                            │   │
│  │  • AGENT_READY      → 预热完成，显示宠物                 │   │
│  │  • LLM_CONFIG_ERROR → LLM 配置错误                       │   │
│  │  • SHUTDOWN         → 请求关闭                           │   │
│  │                                                         │   │
│  │  UI 事件:                                                │   │
│  │  • MOUSE_CLICK      → 鼠标点击                           │   │
│  │  • MOUSE_DRAG_*     → 拖拽开始/移动/结束                 │   │
│  │  • MOUSE_HOVER_*    → 悬停进入/离开                      │   │
│  │                                                         │   │
│  │  AGENT 事件:                                             │   │
│  │  • USER_MESSAGE     → UI → Agent：用户发消息             │   │
│  │  • THINKING         → Agent → UI：正在思考               │   │
│  │  • RESPONSE         → Agent → UI：回复完成               │   │
│  │  • AUTO_SPEAK       → Agent → UI：主动说话               │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  特点:                                                          │
│  • 发布/订阅模式                                                │
│  • 同步调用（发布者的线程执行回调）                              │
│  • 跨线程安全（需要 QTimer.singleShot 桥接）                    │
└─────────────────────────────────────────────────────────────────┘
```

### 跨线程通信问题

EventBus 的回调是**在发布者的线程**执行的：

```python
# 主线程发布
event_bus.publish(AGENT.USER_MESSAGE, message="你好")
# → ChatAgent._on_user_message() 在主线程执行 ✓

# asyncio 协程发布
event_bus.publish(AGENT.RESPONSE, chat_response)
# → Pet._on_agent_response() 可能在协程线程执行
# → QTimer.singleShot 桥接到主线程 ✓
```

## 7. 线程安全注意事项

### 7.1 安全的操作

| 操作 | 线程 | 原因 |
|------|------|------|
| QTimer 回调 | 主线程 | Qt 保证 |
| EventBus 发布 | 任何线程 | 内部无状态 |
| EventBus 订阅 | 任何线程 | 只注册，不在回调 |
| MemoryManager 调用 | 任何线程 | ChromaDB 内部线程安全 |

### 7.2 需要桥接的操作

| 操作 | 问题 | 解决方案 |
|------|------|----------|
| EventBus 回调中的 UI 操作 | 可能非主线程 | `QTimer.singleShot(0, ...)` |
| ChatAgent.chat() | async 函数 | `loop.create_task(...)` |
| 退出流程 | 多线程需同步 | `shutdown_event.wait()` |

### 7.3 禁止的操作

- ❌ 在子线程直接操作 Qt UI（窗口、控件）
- ❌ 在 EventBus 回调中执行耗时操作
- ❌ 多个线程同时操作同一个 Python 对象（无锁）

## 8. 关键设计决策

### 8.1 为什么用 Loop Engineering 而不是 LangGraph？

| 对比项 | LangGraph | Loop Engineering |
|--------|-----------|-----------------|
| 代码量 | 需定义状态图、节点、边 | 一个 while 循环 |
| 调试难度 | 高（状态转换不透明） | 低（直接看代码） |
| 灵活性 | 固定流程 | LLM 自主决策步数 |
| 维护成本 | 高（框架升级） | 低（自研，完全控制） |

简单才是最好的架构。

### 8.2 为什么选择「预热后显示」？

| 方案 | 用户感知 | 问题 |
|------|----------|------|
| 主线程同步初始化 | 卡住 5-10 秒 | 用户看到白屏 |
| 显示后后台初始化 | 立即看到宠物 | 首次对话失败 |
| **后台初始化，预热后显示** | 有进度反馈，就绪后显示 | 需要超时降级 |

我们选择第三种方案，配合 10 秒超时保护。

### 8.3 为什么要保存事件循环引用？

```python
# ChatAgent.__init__
def __init__(self, event_loop=None):
    self._main_loop = event_loop

# 为什么不直接 get_running_loop()？
# 因为 EventBus 回调可能在不同的线程执行
# 如果在后台线程执行，get_running_loop() 会失败
# 保存引用是最可靠的方式
```

### 8.4 为什么用 EventBus 而不是直接调用？

```python
# 直接调用（耦合）
pet.chat_agent.handle_message(msg)

# EventBus（解耦）
event_bus.publish(AGENT.USER_MESSAGE, msg)
# ChatAgent 自己订阅，Pet 不知道 Agent 的存在
```

EventBus 让组件独立，可以随意替换或增减组件。

## 11. 常见问题

### Q1: 为什么有时 UI 会卡住？

可能原因：

- QTimer 回调中有耗时操作（>10ms）
- asyncio 任务执行时间过长（阻塞事件循环）
- Python GC 暂停

排查方法：在耗时操作前后加日志，用时间戳计算耗时。

### Q2: EventBus 回调为什么有时不执行？

可能原因：

- 订阅者已被销毁（GC）
- 没有订阅者，事件被静默忽略
- 回调抛异常被 EventBus 捕获

排查方法：开启 EventBus 的 debug 日志。

### Q3: 如何从后台线程更新 UI？

正确做法：

```python
# ❌ 直接操作 UI → 崩溃！
pet.setText("Hello")

# ✅ 通过 EventBus
event_bus.publish(AGENT.RESPONSE, text="Hello")

# ✅ 通过 QTimer.singleShot 桥接
loop.call_soon_threadsafe(
    lambda: QTimer.singleShot(0, lambda: pet.show_message("Hello"))
)
```

### Q4: 记忆系统为什么不工作？

排查步骤：

```python
from memory import get_memory_manager

manager = get_memory_manager()

# 1. 检查是否初始化
print(f"是否就绪: {manager.is_ready}")

# 2. 检查是否有数据
print(f"记忆数量: {len(manager.get_all_memories())}")

# 3. 手动测试检索
results = manager.search("测试", n_results=3)
print(f"检索结果: {results}")
```

## 12. 总结

| 概念 | 说明 | 本项目实现 |
|------|------|-----------|
| **进程** | 独立资源空间 | 单进程 |
| **线程** | CPU 调度单位 | 主线程 (UI) + 后台线程 (初始化) |
| **协程** | 用户态轻量线程 | asyncio 管理 |
| **事件循环** | 调度协程的核心 | qasync.QEventLoop (Qt+asyncio) |
| **Agent** | 自主决策的核心 | TurnEngine (Loop Engineering) |
| **记忆** | 持久化知识 | ChromaDB + bge-small-zh |
| **桥接** | 连接不同线程 | QTimer.singleShot, EventBus |

**核心原则：**

1. UI 操作永远在主线程
2. 耗时操作用 asyncio 或线程
3. EventBus 解耦组件
4. 跨线程必须桥接
5. 简单优于复杂（Loop Engineering > LangGraph）
