# 记忆归一化（Memory Normalization）

## 核心结论

归一化 = **把多种等价表述映射到单一标准形式（指纹），用于去重/替换判断**。
只影响「去重判断」，**不改变用户原始存储内容**。

## 项目里做什么用

LLM 对同一事实的说法千变万化（"我叫小明" / "用户叫小明" / "其实我叫小明"），
记忆系统需要判断「新旧两条是不是同一件事」，从而：
- 同一条 → 跳过（去重）
- 同字段新值 → 替换旧值（如用户改名）
- 核心不同 → 共存

归一化把表述统一成指纹（如"用户叫小明"），再用 `old_norm == new_norm` 判断。

## 三类记忆怎么归一的

| 类型 | 策略 | 例子 |
|------|------|------|
| FACT（事实） | 去噪声 → 匹配字段(name/birthday/...) → 应用归一化模板 | "我叫小明" → "用户叫小明" |
| PREFERENCE（偏好） | 提取(方向, 核心) | "我喜欢苹果" → "用户喜欢苹果" |
| 其他 | 只去噪声词 | - |

## 三个核心方法（normalizer.py）

- `normalize()`：生成去重指纹
- `extract_field()`：提取字段/核心 → 用于 where 过滤（只查同字段，性能好）
- `correct_type()`：修正 LLM 误判的类型（偏好 > 事实 > 保持），防止同信息以两种类型重复

## 为什么这么做（权衡）

1. **确定性 > 概率性**：规则驱动（正则）比向量相似度可靠——向量召回不全/阈值不稳会导致重复堆积
2. **性能**：先按字段 where 过滤（只查同字段 1-2 条），不全量遍历
3. **热更新**：YAML 规则基于 mtime 检测，改规则下次加记忆自动生效，不用重启
4. **双轨兜底**：归一化做精确去重，向量相似度做语义兜底召回

## 代价（要注意）

- 规则覆盖不到的表达 → 回到 LLM 判断（YAML 注释已说明）
- 模式顺序敏感 → 必须「从长到短」排列，避免短词误伤长词
- 每次归一化有一次 `stat()` 系统调用（热更新代价）

## 归一化思想的通用应用

数据库范式化、特征标准化(Z-score)、URL 去重、日志模板聚合、缓存 key 归一、文本繁简/大小写统一等。
本质都是「降维到标准形式换取可比较性」。
