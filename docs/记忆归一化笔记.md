# 记忆归一化（Memory Normalization）

## 核心结论

归一化 = **把多种等价表述映射到单一标准形式（指纹），用于去重/替换判断**。
在当前架构中，归一化的角色已从「主力提取器」降级为 **LLM 提取的兜底**：

- **主力**：`memory_extract` 节点的 LLM 基于完整对话语义直接提取 `field`（如 `name`、`mother_location`、`桃子`）
- **兜底**：`normalizer` 规则在 LLM 未提取 field 或类型误判时介入修正

## 当前架构下的数据流

```
用户消息 → agent_node → [无工具] → memory_extract_node (LLM 提取 field)
                                  → format_node (LLM 判断 emotion)  [并行]
                                  ↓
                            memory_node (barrier)
                                  ├─ normalizer.correct_type()   ← 类型兜底
                                  ├─ normalizer.extract_field() ← 字段兜底（仅当 LLM field 为空时）
                                  ├─ CoreMemoryCache.update()
                                  └─ MemoryStore.smart_add()
```

## 为什么 LLM 提取 field 是主力

LLM 能理解复杂语义，这是规则模板无法做到的：

| 场景 | LLM 提取 | 规则模板（旧方案） |
|------|---------|------------------|
| "我以前住在成都，现在搬去上海了" | field=`location`，content="用户住在上海" | 无法处理时间变化 |
| "我妈妈住在北京" | field=`mother_location` | 无法区分主体 |
| "我不喜欢桃子，我喜欢梨" | field=`桃子` → 替换为 `梨` | 匹配泛化能力差 |
| "会弹吉他" | field=`弹吉他`，type=`skill` | 容易误判为 `other` |

## normalizer 的兜底职责

### 1. `correct_type()` — 类型修正

当 LLM 误判类型时（如把"不太会弹吉他"判为 `fact`），按优先级修正：

```
preference > fact > 保持原类型
```

### 2. `extract_field()` — 字段提取（fallback）

仅在 LLM 返回的 `field` 为空时，才用 YAML 规则模板兜底：

- 按 `normalize_rules.yaml` 中定义的 pattern 匹配
- 命中规则的直接用模板字段名
- 未命中的返回 `"other"`

### 3. `normalize()` — 生成去重指纹

用于 `smart_add` 中的去重判断，同一条记忆只存一次。

## 三类记忆的归一策略（兜底场景）

| 类型 | 策略 | 例子 |
|------|------|------|
| FACT（事实） | 去噪声 → 匹配字段(name/birthday/...) → 应用归一化模板 | "我叫小明" → "用户叫小明" |
| PREFERENCE（偏好） | 提取(方向, 核心) | "我喜欢苹果" → "用户喜欢苹果" |
| 其他 | 只去噪声词 | - |

## 规则文件

**[memory/res/normalize_rules.yaml](file:///Users/yangchengwei/Documents/workspace/github_workspace/my_baby/memory/res/normalize_rules.yaml)**

- 字段规则：name/生日/住址/妈妈住址 等
- 噪声词："我"、"我的"、"其实"、"好像" 等
- 偏好规则：like/dislike/skill 关键词
- 类型修正：skill → preference 等

## 关键设计决策

1. **LLM-first, normalizer-fallback**：语义理解交给 LLM，确定性规则做兜底
2. **规则热更新**：YAML 文件基于 mtime 检测，改规则不用重启
3. **双轨去重**：LLM field 精确去重 + 向量相似度语义兜底
4. **不改变原始内容**：归一化只影响「去重判断」，不修改用户存储的内容

## 归一化思想的通用应用

数据库范式化、特征标准化(Z-score)、URL 去重、日志模板聚合、缓存 key 归一、文本繁简/大小写统一等。
本质都是「降维到标准形式换取可比较性」。
